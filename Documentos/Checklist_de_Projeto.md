# Checklist de Projeto

**SPG - SmartPark Guarita**

Versão em texto do Checklist de Verificação de Projeto do SpinOff, para a equipe acompanhar. O modelo oficial é uma planilha (`Template - Checklist Verificacao de Projeto.xltx`, no site do SpinOff) com o Indicador de Aderência ao Processo (IAP). O ideal é um IAP entre 70% e 100%.

Todos os itens estão desmarcados. Marque `[x]` só depois de verificar, e preencha a data e o verificador.

| Campo | Valor |
|---|---|
| Data da verificação | |
| Verificador | |

## Iniciação (planejamento)

- [ ] O objetivo, os problemas e as necessidades do cliente estão claros no documento Visão?
- [ ] Foram identificadas restrições de prazo, custo e tecnologia e registradas no Visão?
- [ ] As atas das reuniões de levantamento de requisitos foram aprovadas?
- [ ] A equipe foi definida com seus respectivos e-mails?
- [ ] As necessidades foram descritas como histórias de usuário?
- [ ] O modelo de casos de uso e os atores têm descrições claras, sem precisar de explicação verbal?
- [ ] As especificações dos casos de uso e histórias são testáveis (entradas e saídas identificáveis)?
- [ ] O escopo foi apresentado e aprovado pelo cliente ou representante?
- [ ] Se foi criado o protótipo, ele está na pasta correta do repositório?
- [ ] O backlog do produto foi criado com todos os casos de uso?
- [ ] Foi feita a estimativa e a priorização do Backlog do Produto?
- [ ] O plano de gerenciamento de riscos foi elaborado e considerou as restrições registradas no Visão?
- [ ] O plano de entregas foi definido e corresponde ao número de sprints planejado?
- [ ] O planejamento foi apresentado e aprovado pelo cliente ou representante?

## Elaboração (arquitetura)

- [ ] O caso de uso ou história escolhido para testar a arquitetura foi especificado?
- [ ] O caso de uso escolhido para testar a arquitetura foi implementado e testado?
- [ ] O modelo de arquitetura foi criado e atualizado?
- [ ] Os requisitos suplementares (não funcionais) foram usados na definição da arquitetura?
- [ ] As novas especificações, modelos e protótipos foram aprovados pelo cliente?
- [ ] O Backlog do Sprint foi refeito, com estimativa e priorização?

## Construção (desenvolvimento)

- [ ] Os testes unitários foram executados e todos passaram?
- [ ] O código respeita o modelo de arquitetura, inclusive nomes de classes, atributos e pacotes?
- [ ] Os diagramas de classes e de arquitetura foram criados e atualizados?
- [ ] Foram feitos refinamentos no código para melhorar eficiência ou corrigir bugs?
- [ ] No Backlog do Produto foi incluída mais alguma atividade, estimada e priorizada?
- [ ] O plano de entregas e o plano de riscos foram atualizados?
- [ ] Foram feitas as reuniões de revisão do produto e do processo?

## Transição (testes e entrega)

- [ ] Existe um roteiro de testes com casos de teste para cada caso de uso ou história de usuário?
- [ ] Os dados de entrada e os resultados esperados estão definidos?
- [ ] Existem evidências de execução dos testes (prints)?
- [ ] O guia de implantação ou instruções de instalação do `.apk` foram criados?
- [ ] O manual do usuário (ou ajuda no app) foi feito, se exigido pelo cliente?

## Gerenciamento de configuração e mudanças

- [ ] Os artefatos usam o template atual e estão nas pastas corretas do repositório?
- [ ] A estrutura do projeto (repositório) foi criada e está sincronizada com o servidor (GitHub)?
- [ ] Os históricos de atualização dos artefatos descrevem o que foi alterado?
- [ ] Os artefatos estão nomeados conforme a política de gerência de configuração?
- [ ] O Modelo de Negócio (diagrama de classes ou DER) foi criado e atualizado?
